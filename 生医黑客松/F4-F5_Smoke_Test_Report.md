## F4 — 质量受控整合：30/100 ❌

> 赛题要求：确保合并过程中的医学逻辑准确性。以教学大纲为骨架，实施概念对齐→关系合并→冲突消解。

### ✅ 通过项

| 项目 | 结果 |
|------|------|
| 合并管道存在 | ✅ `cross_textbook_merger.py` 6 步管道完整 |
| 噪声过滤 | ✅ 19 个正则模式，`is_noise_node()` 函数 |
| 实体对齐 | ✅ 精确匹配 + FAISS 语义匹配双路 |
| 合并图/决策日志/冲突报告输出 | ✅ 4 个 JSON 文件在 `merged/` |
| 冲突检测 | ✅ 检测到 1 个冲突 |
| 互补发现 | ✅ 279 条 complement 关系 |

### ❌ 严重问题

#### 1. 去重率仅 2.26%，远不达标

```
指标           当前值        目标值 (Architecture_Design)
─────────────────────────────────────────────────────
节点去重       3015→2947      目标 ≤ 50%
去重率         2.26%          目标 ≥ 50%
边去重         3967→3945      仅减少 22 条
─────────────────────────────────────────────────────
```

**根因**：噪声过滤几乎无效。`is_noise_node()` 仅去除了 68 个节点 (2.26%)。大量前导页节点（编委名单、ISBN、定价、修订说明等）未被过滤。

#### 2. FAISS 语义匹配产生大量假阳性

| 案例 | FAISS 分 | 判断 |
|------|----------|------|
| "局部解剖学" ↔ "淋巴" | 0.755 | ❌ 完全不同的概念 |
| "供基础、临床..." ↔ "静脉" | 0.766 | ❌ 前言 vs 解剖结构 |
| "Regional Anatomy" ↔ "国家卫生健康委员会" | 0.749 | ❌ 英语 vs 出版信息 |
| "局部解剖学" ↔ "临床" | 0.742 | ❌ 学科 vs 泛词 |
| "局部解剖学" ↔ "绪论" | 0.715 | ❌ 学科 vs 通用章节 |

**1888 / 3187 决策**（59%）属于此类低置信度非子串匹配。

**根因**：`cross_textbook_merger.py` 的 `entity_resolution()` 使用了 `auto_merge_threshold=0.85`，但 FAISS 模型的 `text2vec-base-chinese` 对医学短文本的语义区分能力不足。大量 0.70–0.85 的匹配被标记为"待确认"，但既没有教师审核也没有 LLM 二分类判定。

#### 3. 噪音节点混入医学决策

- "建立更" 被精确匹配为"共用标签"，实际是 PDF 碎片
- "系统的" 同样被当作知识节点
- 265/3187 决策涉及前导页噪音

#### 4. 医学概念对齐质量不可信

虽然医学关键词在决策中出现（发热 3 次、炎症 28 次、肿瘤 142 次、感染 185 次），但由于基础 entity resolution 不准确，实际合并质量无法信任。

### 🔧 修复建议

1. **强化噪声过滤**：在 `NOISE_PATTERNS` 中增加更多模式（定价、印张、字数、标准书号、编者个人信息等）
2. **噪声过滤前移**：在 `single_map_builder.py` 的 `clean_label` 中做预过滤，不让前导页节点进入图谱
3. **替换 FAISS 模型**：`text2vec-base-chinese` → 医学领域专用 embedding 模型（如 `m3e-base` 或 `bge-m3`）
4. **接入 LLM 二分类判定**：对 0.60–0.85 的候选对，调用 LLM 判断是否为同一概念（这是 Architecture_Design 指定的方案，但未实现）
5. **提高 auto_merge_threshold**：从 0.85 → 0.92，更保守的自动合并

## F5 — 决策透明化：45/100 ⚠️

> 赛题要求：对每一项整合/去重决策给出明确的理由。支持与学科教师多轮对话，动态优化整合方案。

### ✅ 通过项

| 项目 | 结果 |
|------|------|
| 每条决策有 `rationale` | ✅ 3187/3187 |
| 决策日志 schema 符合 Architecture_Design | ✅ decision_id / type / nodes / books / confidence / rationale / evidence |
| evidence 字段存在 | ✅ 3187/3187 |
| 支持 4 种决策类型 | ✅ merge / conflict / complement / gap |

### ❌ 严重问题

#### 1. rationale 质量低下，公式化

所有决策的 `rationale` 只有两种模板：
- `"精确匹配：多本教材共用标签「X」"` (精确匹配)
- `"语义相似度 0.XX（待确认）：「A」↔「B」"` (FAISS 匹配)

**没有一条决策解释了 WHY 这个合并是合理的**。例如"局部解剖学"和"淋巴"被建议合并，rationale 只说"语义相似度 0.76"，没有说明这两个概念在什么意义上应该合并。

#### 2. evidence 字段空洞

```
证据类型              数量      占比
────────────────────────────────────
FAISS score only       2872      90.1%
来源教材引用            315       9.9%
────────────────────────────────────
```

**90% 的决策将 FAISS 数值当作唯一证据**，没有引用任何原文段落。Architecture_Design 明确要求 evidence 应包含"原文证据句"。

#### 3. Teacher Loop 从未运行

- **0 / 3187 条决策被审核**
- 所有决策的 `resolved: false`，`resolution: ""`
- Architecture_Design 描述的"教师审核面板"、"批准/拒绝/修改/补充"操作均未对接

#### 4. 决策日志与前端未连接

`merge_decisions.json` (~1.7MB) 存在但前端 `agentData.json` 是独立的静态文件，两者没有数据流连接。

### 🔧 修复建议

1. **LLM 生成 rationale**：对每条 merge/conflict/complement 决策，调用 LLM 生成 2-3 句自然语言理由，说明合并的医学逻辑
2. **evidence 引用原文**：从 `triples.json` 中提取节点对应的 `evidence` 字段，写入合并决策
3. **Web 审核面板**：在 `frontend/` 中实现决策审核 UI（已有 mock UI 壳，需对接数据）
4. **决策排序**：按 confidence 升序排列，低置信度决策优先展示给教师
