## 一、赛道核心命题（五大任务）

### 01 / MULTI SOURCE — 多源教材加载

**目标**: 自动加载并解析多本教材与辅助书籍。

**格式要求**:
- PDF（已有 PyMuPDF 管线）
- Markdown（直接读取）
- Word（python-docx）
- Excel（openpyxl）

**设计思路**:
- 所有格式统一转为 **Markdown 中间表示**，下游管线只吃 MD
- 新增格式只需写一个 `→ MD` 的转换器，不动下游
- 封装统一加载接口 `DocumentLoader.load(path) → List[Section]`

**扩展考量**:
- 教材可能含插图/表格，未来可对接多模态模型做图文联合理解
- 辅助书籍可能包含习题集、教案、临床指南等非教材体裁，需在 prompt 中区分处理

### 02 / SINGLE MAP — 单本教材知识图谱构建

**目标**: 为每一本教材独立构建高精度知识图谱。

**四种强制关系类型**:

| 关系 | 英文 | 定义 | 医学示例 |
|---|---|---|---|
| 前置依赖 | prerequisite | A 是学习/理解 B 的前提 | 心脏解剖结构 → 心功能评估 |
| 并列关系 | parallel | A 与 B 同级、同类 | 左心室 ↔ 右心室 |
| 包含关系 | containment | A 包含 B | 心血管系统 ⊃ 心脏 |
| 应用关系 | application | A 的知识应用于 B | 听诊技术 → 瓣膜病诊断 |

**技术方案: LLM 驱动的三元组抽取**

```
┌─────────────┐     ┌──────────────────┐     ┌──────────────────┐
│  Chunk 文本   │ ──→ │ LLM prompt 模板   │ ──→ │ 结构化三元组列表   │
│ "心脏位于..." │     │ (few-shot 医学示例) │     │ [{subject,        │
│             │     │  定义4种关系类型)   │     │   relation,       │
└─────────────┘     └──────────────────┘     │   object,         │
                                              │   evidence}]      │
                                              └──────────────────┘
```

**Prompt 设计要点**:
- 每种关系提供 2-3 个真实医学示例 (few-shot)
- 严格 JSON 输出：`subject`, `relation`, `object`, `evidence`（原文证据句）
- 每 chunk 限制 5-8 个三元组，防止冗余
- `evidence` 字段强制回溯原文，抗幻觉

**存储**: 开发期 NetworkX → 导出 Cytoscape.js JSON → 可视化

**质量标准**:
- 环路检测（前置依赖不能成环）
- 孤立节点标记（度 ≤ 1 的节点需人工复核）
- 与《临床医学专业教学大纲》对齐校验

### 03 / CROSS-TEXTBOOK — 跨教材知识整合 ✅ 已完成

> **实现文件**: `cross_textbook_merger.py`（616 行）
> **输出目录**: `生医黑客松/merged/`
> **完成日期**: 2026-05-10

**目标**: 识别知识点在不同教材间的**重叠、互补与缺失**。

**三步合并流程**:

#### Step 1 — 概念对齐 (Entity Resolution) ✅

不同教材对同一概念用词不同（如"心室收缩期" vs "心脏收缩期"）。

```
节点A (生理学) ──FAISS语义相似度──→ 候选集 ──阈值判定──→ auto_merge / pending_review / different
```

- **精确匹配**: 35 组跨教材相同标签自动合并（confidence=0.95）
- **FAISS 语义匹配**: 2,872 个候选对，其中 67 组 ≥0.88 自动合并，其余 2,805 组标记为待审核（0.70-0.88）
- **阈值**: >0.85 自动合并 / 0.70-0.85 标记待教师确认 / <0.70 视为不同

#### Step 2 — 关系合并与冲突消解 ✅

两本教材可能对同一概念有不同关系定义：

- **冲突检测**: 发现 1 处方向冲突（自环 containment），无 prerequisite 环路
- **互补发现**: 发现 279 处互补关系——某教材中存在但另一教材中缺失的关联

#### Step 3 — 缺失发现 ⏳

以教学大纲为骨架，扫描整合后的全局图谱（待大纲数据接入）

#### 实测运行数据

```
加载 7 本教材 → 9,391 triples / 4,860 nodes
    ↓ 噪音过滤（34-84% 移除）
剩余 4,031 triples / 3,015 nodes
    ↓ 概念对齐（FAISS + 精确匹配）
生成 3,187 条整合决策
    ↓ 关系合并
发现 1 冲突 + 279 互补
    ↓ 质量验证
合并图：2,947 nodes / 3,945 edges
  环路: 1 total / 0 prerequisite 环路 ✅
  孤立节点: 986 (33.5%)
  关系分布: containment 2,080 | parallel 823 | prerequisite 770 | application 272
```

#### 输出物

| 文件 | 说明 |
|---|---|
| `merged/merged_graph.json` | 合并后的 NetworkX node-link 图 |
| `merged/merged_cytoscape.json` | Cytoscape.js 前端直读格式 |
| `merged/merge_decisions.json` | 3,187 条整合决策日志（含理由、证据、置信度） |
| `merged/merge_report.json` | 完整整合报告（含统计摘要） |

#### 已知局限

- 输入三元组为 `rule_based` 提取（heading 层级 + 章节顺序），缺少语义深度。去重比仅 2.3%。
- 概念对齐用到 FAISS 文本匹配和精确标签匹配，未接入 LLM 精排（等待 API key）。
- 缺失发现依赖教学大纲数据（尚未接入）。

### 04 / 30% ESSENCE — 精华压缩 ✅ 已完成

> **实现文件**: `essence_compressor.py`（872 行）
> **输出目录**: `生医黑客松/essence/`
> **完成日期**: 2026-05-10

**目标**: 将多本教材内容压缩至原始体量的 **30% 以内**，保留核心精华。

**实测压缩比**: **20.5%**（266,727 chars / 1,301,865 chars）✅

**三步压缩法**:

1. **去重 (Deduplicate)**
   - 跨教材重复知识点只保留一份最详尽的描述
   - 保留不同教材的 evidence 引用，但不重复存储相同文本

2. **摘要 (Summarize)**
   - 对每个合并后的知识点，LLM 生成一句话摘要
   - 本质定义 + 关键数据 + 临床联系，控制在 80 字以内

3. **分级保留 (Tiered Retention)**
   - Tier 1（核心）: 教学大纲明确要求掌握的知识点 → 完整保留
   - Tier 2（重点）: 大纲要求理解的知识点 → 保留摘要 + 关键原文段落
   - Tier 3（了解）: 大纲要求了解的知识点 → 仅保留摘要
   - Tier 4（拓展）: 超出大纲但被多本教材提及的知识点 → 一行提及

**量化指标**:
- 压缩比 = 精华版总字数 / 原始教材总字数 ≤ 30%
- 核心知识点覆盖率 ≥ 95%（以大纲为基准）
- 去重后的知识节点数 / 原始节点数 ≤ 50%

**实测运行数据（2026-05-10）**:

| 指标 | 数值 |
|---|---|
| 原始 chunks 总字符数 | 1,301,865 |
| 精华版总字符数 | 266,727 |
| 压缩比 | **20.5%** ✅ |
| 原始节点数 (merged graph) | 2,947 |
| 噪音过滤后节点数 | ~2,400 |
| 代表性节点数 (去重后) | 2,679 |
| Tier 1 (核心) | 402 条 |
| Tier 2 (重点) | 804 条 |
| Tier 3 (了解) | 937 条 |
| Tier 4 (拓展) | 536 条 |
| 管线耗时 | ~80s |

**实现细节**:

1. **去重**: 基于 `merge_decisions.json` 中 ≥0.70 置信度的合并决策，将重复知识节点分组，每组保留内容最丰富的代表节点；同时用 FAISS 语义搜索将节点映射到原始 chunk，同 chunk 内节点共享内容引用。

2. **自动分级（无教学大纲代理）**: 利用 NetworkX 计算 PageRank（40%）、度中心性（35%）、聚类系数（25%）综合得分，按百分位分割为 Tier 1（top 15%）/ Tier 2（15-45%）/ Tier 3（45-80%）/ Tier 4（bottom 20%）。

3. **摘要生成**: 规则提取（匹配节点标签所在段落的首句实质内容，限 80 字）；支持可选 Ollama（qwen2.5:3b）增强摘要质量。

4. **分级输出**:
   - Tier 1: 完整 Markdown 条目 + 摘要 + 原文摘录（300 字截断，折叠显示）
   - Tier 2: 完整条目 + 摘要 + 关键段落（2 条，每条 120 字截断）
   - Tier 3-4: 紧凑列表格式 `- **标签**: 摘要`，大幅减少 Markdown 开销

5. **噪音过滤**: 多正则模式 + 人名检测，移除版权/编委/前导页/页码/碎片等非知识节点（清理率 ~15%）。

**输出物**:

| 文件 | 说明 |
|---|---|
| `essence/essence.md` | 精华版 Markdown（266K chars，4 级分层） |
| `essence/essence_report.json` | 统计报告 + Tier 样例节点 |

### 05 / TEACHER LOOP — 教学反馈闭环

**目标**: 通过与学科教师的多轮对话，迭代优化整合方案。

**整合决策日志结构**:

```json
{
  "decision_id": "merge_042",
  "type": "merge | split | reject | supplement",
  "nodes": ["生理学/第四章/心脏收缩", "解剖学/第三章/心室收缩"],
  "confidence": 0.88,
  "rationale": "两个节点描述同一生理过程。《生理学》侧重功能机制，《局部解剖学》侧重结构基础。合并后保留两本教材的 evidence。",
  "evidence": ["原文证据1...", "原文证据2..."],
  "teacher_feedback": null,
  "status": "pending_review"
}
```

**多轮对话交互流程**:
1. 系统展示整合建议列表（按置信度排序，low-confidence 优先展示）
2. 教师对每条决策：**批准 / 拒绝 / 修改 / 补充**
3. 教师反馈被记录，用于调整后续自动决策的相似度阈值
4. 支持**回退**：教师否定后图恢复原状
5. 支持**追问**：教师可要求系统解释特定决策的详细理由

**教师操作界面**:
- 侧边栏：待审核决策队列
- 主视图：图谱可视化，被审核节点高亮
- 操作按钮：✓ 批准 / ✗ 拒绝 / ✎ 修改关系 / ⊕ 补充知识点

## 四、关键技术选型

### LLM 方案

| 方案 | 模型 | 优势 | 劣势 | 场景 |
|---|---|---|---|---|
| 本地 Ollama | Qwen3 / DeepSeek | 免费、离线、比赛稳定 | 质量略低于云端 | 比赛现场主方案 |
| 云端 API | DeepSeek API | 质量最高 | 依赖网络 | 开发调 prompt |
| 混合 | 云端开发 + 本地部署 | 兼顾质量与可靠性 | 需维护两套 | **推荐** |

### 前端可视化: Cytoscape.js

选用理由：
- 生物信息学/生物医学领域事实标准
- 内置 dagre(层级)、cose(力导向)、breadthfirst 等多种布局
- 原生支持节点点击展开/收起、筛选、高亮路径
- 可导出为 PNG/SVG 图片

### 图存储: NetworkX → JSON

- 开发期: NetworkX (Python, 轻量, 易调试)
- 前端: JSON 格式直接喂 Cytoscape.js
- 不推荐 Neo4j: 比赛时间紧, 部署维护成本高

### 后端: FastAPI

- 轻量、高性能、自带 Swagger 文档
- 异步支持, 适合 LLM 调用的长请求
- Python 生态无缝对接现有检索/抽取管线

## 六、风险与应对

| 风险         | 影响                 | 应对                           |
| ---------- | ------------------ | ---------------------------- |
| LLM 幻觉     | 错误的三元组污染图谱         | `evidence` 字段强制回溯原文, 输出前验证   |
