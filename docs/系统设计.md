## 一、系统架构

### 1.1 架构风格

**单编排器 + 四阶段顺序流水线**。`kia_agent.py` 作为总入口，按 01→02→03→04 顺序编排各阶段。每阶段是独立的 Python 模块，可单独运行和测试。

### 1.2 技术选型

| 层级 | 技术 | 选型理由 |
|---|---|---|
| 后端编排 | Python 3.8+ | 科学计算生态（NetworkX, FAISS, PyMuPDF） |
| 前端框架 | Next.js 16 (React 19) | TypeScript 类型安全，SSR + API Routes |
| 可视化 | react-force-graph-2d | 力导向图，Canvas 渲染，支持 200+ 节点流畅交互 |
| 图存储 | NetworkX → JSON | 开发期轻量，无需数据库 |
| 向量模型 | text2vec-base-chinese | 中文语义，本地运行 |
| 向量检索 | FAISS (IndexFlatL2) | 暴力检索，适合 < 10K chunks |
| 关键词检索 | BM25 (rank_bm25) | 医学专有名词精确匹配 |
| 文件解析 | PyMuPDF / python-docx / openpyxl | 覆盖 PDF/Word/Excel |
| LLM | 预留 DeepSeek API 接口 | 当前管线不依赖 LLM（规则抽取） |

## 二、API 设计

### 2.1 API Routes

| 路由 | 方法 | 功能 | 状态 |
|---|---|---|---|
| `/api/upload` | POST | 文件上传（PDF/MD/DOCX/XLSX） | ✅ 含 fallback 到本地存储 |
| `/api/feedback` | POST | 教师反馈提交 → 写入日志 | ✅ |
| `/api/rag` | POST | RAG 问答（检索 + LLM 生成） | ⏳ 待实现 |

### 2.2 API 请求/响应示例

**POST `/api/rag`** (规划中)

请求：
```json
{
  "question": "二尖瓣狭窄的临床表现有哪些？",
  "top_k": 5
}
```

响应：
```json
{
  "answer": "二尖瓣狭窄的典型临床表现包括：1. 呼吸困难...",
  "citations": [
    {
      "source": "《病理学》第十一章，第 245 页",
      "snippet": "二尖瓣狭窄时，左心房压力升高..."
    },
    {
      "source": "《生理学》第四章，第 112 页",
      "snippet": "二尖瓣狭窄导致左心房后负荷增加..."
    }
  ],
  "retrieval_scores": [0.92, 0.87]
}
```

**POST `/api/feedback`**

请求：
```json
{
  "nodeId": "merged_node_042",
  "nodeName": "心室收缩",
  "decisionId": "decision_00187",
  "feedback": "《生理学》的描述侧重功能机制，建议保留两份原文并标注各自侧重。"
}
```

响应：
```json
{
  "success": true,
  "message": "Feedback recorded successfully"
}
```

## 三、数据模型

### 3.1 Section（统一加载输出）

```typescript
interface Section {
  title: string;
  markdown: string;
  source_path: string;
  source_type: "pdf" | "markdown" | "docx" | "xlsx";
  book_id: string;
  index: number;
  page_start?: number;
  page_end?: number;
  sheet_name?: string;
}
```

### 3.2 KnowledgeTriple（图谱三元组）

```typescript
interface KnowledgeTriple {
  subject: string;
  relation: "prerequisite" | "parallel" | "containment" | "application";
  object: string;
  evidence: string;
  source_path: string;
  book_id: string;
  chapter: string;
  section: string;
  confidence: number;
}
```

### 3.3 MergeDecision（整合决策）

```typescript
interface MergeDecision {
  decision_id: string;
  type: "merge" | "conflict" | "complement" | "gap";
  nodes: string[];
  books: string[];
  confidence: number;
  rationale: string;
  evidence: string[];
  resolved: boolean;
  resolution: string;
  teacher_feedback?: string;
}
```
